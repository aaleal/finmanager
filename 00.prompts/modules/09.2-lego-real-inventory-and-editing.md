# Module 9.2 — LEGO Collection Catalog: Real Inventory and Full Editing

## 1. Purpose and Scope

A second extension of [Module 9](09-lego-collection-catalog.md), written after
loading the household's actual spreadsheet into the application. It changes
**two columns and nothing else**: `release_year` and `retired_year` become
`release_date` and `retirement_date`.

Everything else here is surface: the seed becomes the real collection, the detail
sheet stops being half read-only, the storage filter stops opening as a wall of
shelves, and thousands stop running together.

Modules 9 and 9.1 remain the specification of record. This document states the
deltas.

## Actors
Unchanged (M9).

## User Stories

### US01. My Actual Collection
As the owner of the spreadsheet in `seed/Lego/`, I want the seeded database to be
my real collection, so I am evaluating the application against my own data rather
than against six invented sets.

### US02. Retirement That Waits for December
As a collector, I do not want a set that retires on 31 December flagged as
«retirado» in January. The year is not precise enough to answer "can I still buy
this?".

### US03. Editing the Set I Already Have
As a user who opened a set and found the theme blank, the PVP wrong or the
retirement date newly announced, I want to correct it in place — not delete the
copy and register it again.

### US04. Readable Thousands
As a user reading a column of euros, I want `1 234,56 €`, not `1234,56 €`.

### US05. A Storage Filter That Starts Small
As a user with five areas and eleven containers, I want the arrumação filter to
open as a short list of areas, and to expand an area only when I want a specific
shelf.

## Data Model

### Changed Columns — `LegoSetModel`

| Was | Now | Notes |
| :--- | :--- | :--- |
| `release_year` (`INTEGER`) | `release_date` (`DATE`) | Year-only sources anchor to 1 January |
| `retired_year` (`INTEGER`) | `retirement_date` (`DATE`) | Year-only sources anchor to **31 December** |

`is_retired` is no longer "the column is not null". It is
`retirement_date IS NOT NULL AND retirement_date <= today`, so an announced future
retirement is visible without pretending the set has already gone.

The 31 December anchor is the point: a set whose retirement was only ever known to
the year stays on sale for that whole year, which is the behaviour the year column
got wrong. See
[ADR-0012](../../docs/decisions/0012-lego-retirement-is-a-date.md).

### New Derived Fields
Computed on read, persisted nowhere.

| Field | On | Definition |
| :--- | :--- | :--- |
| `release_year` | `LegoSetModelOut` | `release_date.year`, or `NULL` |
| `retired_year` | `LegoSetModelOut` | `retirement_date.year`, or `NULL` |

They exist so the grid can keep the compact «2022 › 2024» column M9.1 UX-9.10
asked for, while the database keeps the precision.

## Functional Requirements

- **FR-9.23 Full Catalog Editing.** Every writable field of `LegoSetModel` —
  `set_number`, `name`, `theme`, `subtheme`, `release_date`, `retirement_date`,
  `piece_count`, `minifig_count`, `rrp_eur`, `current_value_eur`,
  `short_description`, `notes`, cover image — is editable from the detail sheet,
  through the `PATCH /lego/models/{id}` and `PUT /lego/models/{id}/image`
  endpoints that already existed. `is_custom` is not editable: a MOC does not
  become an official set.
- **FR-9.24 Date-Accurate Retirement.** The `retirement` filter, the `retirado`
  badge, the row tint and the overview's retired-sets count all resolve through
  `retirement_date <= today`. `sort=year` orders by `release_date`.
- **FR-9.25 Year-Only Sources Anchor Explicitly.** Brickset publishes a release
  *year* and a `dateLastAvailable` timestamp. The year becomes 1 January; a full
  timestamp is used as-is; a bare year becomes 31 December. Nothing is invented
  beyond that rule, and the rule is the same one the migration applied.
- **FR-9.26 Space-Grouped Thousands.** The money/number formatter groups
  thousands with a non-breaking space at every magnitude, including four-digit
  amounts that pt-PT leaves ungrouped by default.

## Seed

The LEGO seed is the household's real inventory, converted once from
`seed/Lego/Lego_Inventory.xlsx` into a committed JSON data file, plus a small set
of hand-written entries kept because the spreadsheet contains no example of them:
a sale, a gift with no cost basis, a MOC, a missing part, and a retirement date
still in the future.

Rules the conversion follows, so the seed never invents data:

- The `Local` column is one free-text label; it is split into the module's flat
  `area` + `container` pair (`BW603 (Right)` → `Sala` › `Estante BW603 (direita)`).
- `Buy €` of `0` means the price paid was never written down. The copy keeps a
  zero cost basis, so cost ROI stays `NULL` and the PVP reading takes over
  ([ADR-0010](../../docs/decisions/0010-lego-cost-roi-and-rrp-roi.md)) — no
  number is guessed.
- The sheet carries no release or retirement information, so both dates stay
  `NULL` for every imported set.
- Repeated set numbers (four `71049`, two `71050`) become one catalog entry with
  four and two copies — not four and two sets.
- The `Legacy` sheet's `Status` maps to `condition` + `missing_parts`
  (`OK` → complete, `MISSING` → the listed parts, `Damaged (light|Heavy)` →
  `WORN` / `DAMAGED`), and its BrickLink links land in `notes`.
- One casing typo (`icons`) is normalised so the theme filter does not split in
  two. Nothing else in the sheet is corrected.

## UI / Screens

### UX-9.17 Set Editing
The detail sheet gains an «Editar conjunto» tab beside «Editar cópia». The split
is deliberate and stated on screen: the copy tab holds what is true of *this
box*, the set tab holds what is true of *every copy*. `set_number` is disabled
for a MOC.

### UX-9.18 Dates in the Detail Sheet
The set section shows `Lançamento` and `Retirada` as dates. A retirement date
still in the future is shown greyed with «(ainda à venda)», so an announced
retirement is never mistaken for a past one.

### UX-9.19 Collection Columns
**Unchanged.** The `Ano` column keeps showing release and retirement *years*,
because that is the reading that fits a table.

### UX-9.20 Storage Filter
A popover tree rather than a flat list. Areas render collapsed with a chevron and
a count; expanding one reveals its containers. Selecting an area means "everything
in it" (FR-9.16, unchanged); selecting a container narrows to it. `StorageLocation`
remains flat in the database — only this control is hierarchical.

### UX-9.21 Numbers
`1 234,56 €` everywhere money, counts, pieces and percentages are rendered,
through the single formatter.

## Edge Cases & Business Rules

- **A retirement date in the future.** The set is *not* retired: no badge, no row
  tint, and it answers `retirement=available`. The date is still shown.
- **A migrated year.** `retired_year = 2023` became `2023-12-31`, so a set that
  the old column flagged as retired all through 2023 is now correctly retired only
  from the last day of it.
- **A retirement date before the release date.** Refused at the schema level.
- **Editing `current_value_eur` from the set tab.** Re-stamps `value_updated_at`
  exactly as the inline value editor does — one rule, two entry points.
- **A set with no dates at all.** The grid's `Ano` column shows `—`; most of the
  imported inventory is in this state, and nothing estimates a year for it.

## Deferred (explicitly not built now)

- Backfilling release or retirement dates for the imported inventory from an
  external source — the lookup exists and is a user action, not a migration.
- A precision flag distinguishing "31 December because that is the date" from
  "31 December because only the year was known"; the anchor rule is documented
  and identical everywhere, which is cheaper than a column.
- Editing `is_custom`, or moving a set between entities from the detail sheet.
- Re-running the spreadsheet conversion automatically; it is a one-shot import.

## Definition of Done

- [ ] One migration converts both year columns to dates, anchoring release to
      1 January and retirement to 31 December, and is reversible.
- [ ] `is_retired`, the `retirement` filter, the badge, the row tint and the
      overview count all agree, and all wait for the date to pass.
- [ ] `LegoSetModelOut` still carries `release_year` / `retired_year`; the
      collection table is visually unchanged.
- [ ] Every `LegoSetModel` field except `is_custom` is editable from the detail
      sheet, and saving `current_value_eur` there re-stamps the freshness date.
- [ ] `./fm seed` loads the real inventory idempotently: 93 imported sets, the
      repeated set numbers collapsed into multi-copy entries, and five storage
      areas.
- [ ] `eur('1000')` renders `1 000,00 €`; the formatter is the only place that
      knows.
- [ ] The storage filter opens showing areas only, and expanding is a per-area
      choice.
