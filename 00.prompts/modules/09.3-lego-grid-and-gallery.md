# Module 9.3 — LEGO Collection Catalog: Reading the Grid and Seeing the Set

## 1. Purpose and Scope

A third extension of [Module 9](09-lego-collection-catalog.md), written after
loading the real collection and finding that 105 copies read very differently from
seven. It adds **one table** — the set gallery — and changes no other column.

Everything else is about getting information out of a grid that is now big enough
to need it: sorting on every column, a filter for repeated sets, a name that does
not push the table off-screen, and a page size the user picks.

Modules 9, 9.1 and 9.2 remain the specification of record.

## Actors
Unchanged (M9).

## User Stories

### US01. Sort by Anything I Can See
As a user, I want to order by any column the table shows — number, theme, storage,
condition, PVP, ROI — not by the five fields somebody chose in advance.

### US02. Find the Sets I Bought Twice
As a collector, I want to see which sets I own more than one copy of, because that
is either a deliberate investment or a mistake I should know about.

### US03. A Table That Fits
As a user, I want all ten columns on screen at once. Today one long set name pushes
ROI behind a horizontal scrollbar.

### US04. Choose How Much I See
As a user with a hundred copies, I want to page through them fifty or a hundred at
a time, not twenty-five.

### US05. See the Actual Set
As a user, I want the thumbnail to be the box, so I recognise a set the way I do on
a shelf — not a coloured tile.

### US06. Look Closer
As a user, I want more than one image per set: the box to identify it, and other
views to inspect what is actually inside.

## Data Model

### New Table — `LegoSetImage`

| Column | Type | Notes |
| :--- | :--- | :--- |
| `id` | UUID | Primary key |
| `lego_set_model_id` | UUID (FK, cascade) | The set this view belongs to |
| `document_id` | UUID (FK documents) | The stored image |
| `position` | Integer | Order within the carousel |
| `caption` | String(200) ▪ Nullable | Optional label |
| `created_at` | DateTime(tz) | |

Unique on `(lego_set_model_id, document_id)`. `LegoSetModel.image_document_id` is
**unchanged** and still means "the box"; this table holds only the extra views. See
[ADR-0013](../../docs/decisions/0013-lego-set-gallery.md) for why the module's
"three tables only" rule gives way here and nowhere else.

## Functional Requirements

- **FR-9.27 Sort on Every Column.** `sort` accepts `created`, `number`, `name`,
  `theme`, `copies`, `pieces`, `minifigs`, `year`, `retired`, `storage`, `state`,
  `condition`, `acquired`, `cost`, `rrp`, `value`, `ownership` and `roi`. Two are
  not columns: `copies` is a correlated count of live copies of the same set, and
  `roi` is the same arithmetic as `roi_pct`, so a gift sorts as absent rather than
  as zero. `NULL`s stay last in both directions (FR-9.15, unchanged).
- **FR-9.28 Ordinal Scales Sort by Meaning.** `condition` orders
  `NEW → GOOD → WORN → DAMAGED` and `state` orders `SEALED → BUILT → DISASSEMBLED`,
  through a CASE rank. Alphabetical order on these columns is meaningless and would
  put `DAMAGED` first.
- **FR-9.29 Stable Paging.** Every ordering carries `created_at DESC` as a
  tiebreaker, so equal values cannot shuffle between pages.
- **FR-9.30 Copies Filter.** `copies` is tri-state (`all` | `multiple` | `single`)
  over the same count `sort=copies` uses.
- **FR-9.31 Page Size.** `page_size` is chosen by the user from 10 / 25 / 50 / 100 /
  200. Changing it, or any filter, returns to page 1.
- **FR-9.32 Set Gallery.** `POST /lego/models/{id}/images` adds a view from a URL or
  an upload, `POST …/images/{image_id}/cover` promotes one to the box shot and
  demotes the current box into the gallery, `DELETE …/images/{image_id}` removes the
  link (never the `Document`), and `PATCH …/images/{image_id}` edits caption and
  position. `LegoSetModelOut.images` carries the gallery, ordered.
- **FR-9.33 Real Box Art in the Seed.** The seed fetches each set's box shot and up
  to three additional views from Brickset's predictable image paths, downloading
  once and storing locally (§1a Document) — never hotlinking. Every fetch is
  best-effort: an offline NAS, a MOC or a set nobody photographed falls back to the
  generated placeholder, and `--offline` skips the network entirely.

## UI / Screens

### UX-9.22 Sortable Headers
Every column header is a button: click to sort by it, click again to flip the
direction. The active column shows an arrow, inactive ones reveal a faint marker on
hover. Text columns open ascending, numbers descending. The existing sort `Select`
stays and lists every field, because `Adicionado` has no column.

### UX-9.23 Column Widths
The set name is capped and truncates with the full name in a `title`, which is what
keeps ten columns inside the viewport. It is the only free-text column, so it is
the only one capped.

### UX-9.24 Pagination
Rows-per-page selector, the range in words (`26–50 de 105`), and first / previous /
next / last. Shown whenever there is data, not only when it overflows.

### UX-9.25 Carousel
The detail sheet's header image becomes a carousel: the copy's photograph if there
is one, then the box, then the gallery. Arrows on hover, a counter, a caption strip
and a thumbnail row. One image renders as a plain image with no controls.

The «Editar conjunto» tab gains a gallery editor: the cover marked as such, each
extra view with «tornar principal» and «remover», and inputs to add by file or URL.

## Edge Cases & Business Rules

- **Sorting by ROI.** Gifts and unvalued sets have no ROI and sort last in *both*
  directions, exactly as the grid shows `—`.
- **Sorting by storage.** Copies with no location sort last; the join is outer, so
  they never disappear.
- **The same image twice.** Documents are content-addressed, so re-uploading a file
  already in the gallery is refused with a `409` instead of creating a duplicate.
- **Promoting with no cover.** A set that never had a box shot simply gains one;
  nothing is demoted.
- **Deleting a gallery image.** Removes the link. The `Document` stays, because it
  is content-addressed and may be shared with another set.
- **A MOC.** No set number means no Brickset lookup, so it keeps the generated
  placeholder and an empty gallery.

## Deferred (explicitly not built now)

- Drag-and-drop reordering of the gallery; `position` exists, promotion is the only
  way to change it.
- Captions in the seeded gallery — Brickset does not say what each view is.
- A lightbox or full-screen viewer.
- Fetching box art for sets the user adds by hand; the Brickset lookup already
  offers an image URL on an explicit action.
- Multi-column sort.

## Definition of Done

- [ ] One migration adds `lego_set_images` and nothing else.
- [ ] Every value in `SORT_FIELDS` returns rows in both directions, including
      `copies` and `roi`.
- [ ] `condition` and `state` sort by meaning, not alphabetically.
- [ ] `copies=multiple` and `copies=single` partition the collection.
- [ ] The ungrouped table renders without horizontal scroll at 1600 px.
- [ ] Page size is user-chosen and any filter change resets to page 1.
- [ ] `./fm seed` gives 99 of 100 sets a real JPEG box shot and fills the gallery;
      `--offline` produces the same row counts with placeholders.
- [ ] Adding, promoting and deleting a gallery image all work and are audited.
